# Generated Computation, Certificates and the P vs NP Problem

A finite computation should specify more than a truncated answer. It should
record the input presentation, the construction used, the error needed by the
observation and the cost of checking the result. The generated-spectrum papers
develop this connection from function classes to finite rational records.

## Generated functions and finite observation

Certified presentations retain a finite construction and an explicit remainder.
Interaction-compatible spectral weights control nonlinear products. Full
quadratic ledgers keep signed cross terms, and nonlinear Galerkin estimates
combine the finite trajectory with its discarded tail and return through
memory. These structures distinguish the cost of generating a result from the
cost and precision of reading it.

## A polynomial-cost trajectory theorem

For the Neumann equation u_t = u_xx + u^2 on the interval [0, pi] up to time
1/16, the computation paper uses rational cosine data satisfying its stated
weighted input bound. Every admissible input has a finite rational Taylor
record whose residual can be checked independently. With complete input length
n and unary accuracy m, the construction and checking costs are polynomial in
n+m. The record payload is O((m+1)^7), and the full record length is
O(n+(m+1)^7).

A coupled linear Picard model separates finite execution from the underlying
evolution. Robust witness decoding makes explicit the precision and separation
needed to turn a generated continuous response into a discrete answer.

## The complexity-theoretic connection

The paper defines certified relations in a generated framework whose uniform
generation, precision and decoding costs are part of the mathematical data.
Within this framework it proves CR_F = P_F. The connection to the standard
P vs NP problem is then precise: if every NP verifier language admits the
specified uniform certified generation route, the decoding theorem gives a
deterministic polynomial-time decision procedure for every such language.

This formulation identifies the constructive content of the proposal. The
relevant object is a uniform family of generation records with a polynomial
resource bound and robust decoding, rather than a short verification procedure
alone. The nonlinear evolution example supplies a complete finite-record
theorem within the programme.
